# Task2-Example3：Aptos Keyless JWT 载荷承诺

## 案例背景

Aptos Keyless 让用户能够基于现有 OpenID Connect 账户建立区块链账户，而不需要直接管理传统长期私钥。零知识电路验证 JWT 中的身份与会话信息，并在不公开完整凭据内容的情况下生成账户相关承诺。

## 代码在项目中的位置

本案例是从 Aptos Keyless 电路的 Base64URL 长度处理和 JWT 消息承诺逻辑提炼出的研究用对齐版本。`KeylessCircuit` 调用 `KeylessProof` 和 `KeylessMessage`，计算编码载荷的解码长度、检查头部摘要，并把载荷、长度、头部及账户盐组合为最终承诺。

案例使用固定长度数组和简化摘要代替完整 JWT 解析与密码学哈希，但保留了编码长度和账户承诺之间的预期数据依赖。

## 预期功能

1. 根据 `encodedPayloadLength` 确定性地计算解码后载荷长度。
2. 汇总 JWT 头部并与 `expectedHeaderTag` 比较。
3. 将载荷内容、解码长度和头部摘要组合为消息承诺。
4. 使用 `accountSalt` 对消息承诺进行账户级绑定，输出最终 `commitment`。

## 输入信号及其语义

| 输入信号 | 形状 | 语义 |
|---|---:|---|
| `encodedPayloadLength` | 标量 | Base64URL 编码后的 JWT 载荷长度。 |
| `payload` | `[8]` | 研究案例中用于表示 JWT 载荷内容的八个元素。 |
| `header` | `[8]` | 研究案例中用于表示 JWT 头部的八个元素。 |
| `expectedHeaderTag` | 标量 | JWT 头部应当匹配的预期摘要。 |
| `accountSalt` | 标量 | 将凭据消息绑定到具体 Keyless 账户的私有盐值。 |

## 输出信号及其语义

| 输出信号 | 形状 | 语义 |
|---|---:|---|
| `commitment` | 标量 | 绑定 JWT 载荷、正确解码长度、头部摘要和账户盐的账户承诺。 |

## 必须满足的关键安全与功能性质

1. **长度确定性**：解码长度必须由编码长度按规定规则唯一确定。
2. **载荷绑定**：消息承诺必须绑定完整 `payload` 和相应解码长度。
3. **头部一致性**：头部摘要必须等于 `expectedHeaderTag`。
4. **账户隔离**：不同 `accountSalt` 应产生不同的账户级承诺关系。
5. **端到端一致性**：最终 `commitment` 必须由同一组 JWT 数据、长度和账户上下文确定。

## 必要术语

- **Aptos Keyless**：利用 OpenID Connect 凭据和零知识证明建立 Aptos 账户授权关系的机制。
- **JWT**：由头部、载荷和签名组成的结构化身份令牌。
- **Base64URL**：JWT 用于编码头部和载荷的 URL 安全文本编码形式。
- **解码长度**：编码文本还原为原始字节后应具有的长度。
- **Salt（盐值）**：加入承诺计算、用于隔离账户或提高隐藏性的附加秘密值。
- **承诺**：隐藏原始数据、同时将证明绑定到确定内容的固定大小表示。
