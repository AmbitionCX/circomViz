# Case 01：Zkopru 交易所有权授权

## 案例背景

Zkopru 是一个面向以太坊的隐私型 Layer 2（第二层）协议。它将多笔交易放在链下处理，并使用零知识证明及链上验证机制，在降低主链负担的同时保护交易隐私。

在 Zkopru 中，可花费的资产以 UTXO（未花费交易输出，也称为 note）表示。note 的具体内容不直接公开，而是以承诺的形式参与系统状态。用户花费一个 note 时，需要证明该 note 与系统记录的承诺一致，并证明本次交易得到了 note 所有者的授权。

## 代码在项目中的位置

本案例是从 Zkopru 电路库中的所有权证明逻辑提炼出的研究用对齐版本。该逻辑位于交易输入的授权检查环节：rollup 入口组件调用转账授权组件，转账授权组件进一步检查 note 承诺和所有者签名。

为了让实验案例具有可控且相近的规模，本版本简化了生产系统中的密码学运算、外围组件和业务数据，但保留了与任务相关的组件层次、主要数据流和预期安全语义。因此，应当依据本案例给出的信号和约束理解代码，不应将其中的简化算术视为完整的生产级密码学实现。

## 预期功能

该电路用于判断一次 note 转账是否获得了合法所有者的授权。它应当完成以下工作：

1. 根据 note 的秘密值和当前交易上下文构造待授权消息。
2. 使用所有者公钥验证该消息对应的 EdDSA 签名。
3. 根据所有者公钥和 note 秘密值计算所有者承诺，并与给定的预期承诺进行比较。
4. 仅当签名有效且承诺匹配时，接受本次转账授权。

## 输入信号及其语义

主入口为 `RollupEntry`。本案例编译时没有声明显式公开输入，因此下列入口输入均作为私有 witness 提交。

| 输入信号 | 形状 | 语义 |
|---|---:|---|
| `ownerKey` | `[2]` | note 所有者的 EdDSA 公钥，两个元素表示公钥点的两个坐标。 |
| `signatureR8` | `[2]` | EdDSA 签名中曲线点 `R8` 的两个坐标。 |
| `signatureS` | 标量 | EdDSA 签名的标量部分，与 `signatureR8` 共同构成签名。 |
| `noteSecret` | 标量 | 与待花费 note 及其承诺相关的私有秘密值。 |
| `context` | `[8]` | 与本次授权相关的八个交易上下文字段；这些字段共同参与待授权消息的构造。 |
| `expectedCommitment` | 标量 | 本次授权应当匹配的既有 note/所有者承诺。 |

## 输出信号及其语义

| 输出信号 | 形状 | 语义 |
|---|---:|---|
| `accepted` | 标量 | 主入口的授权结果。预期语义中，`1` 表示所有者签名有效且计算出的承诺与 `expectedCommitment` 匹配。 |

`ownerCommitment`、`authorizationValid` 和 `transferApproved` 是中间组件产生的内部结果，分别用于表示计算出的承诺、所有权授权结果和转账授权结果；它们最终汇总为主入口输出 `accepted`。

## 必须满足的关键安全与功能性质

1. **合法授权可接受**：合法所有者使用匹配的密钥、消息和承诺时，应当能够构造满足电路约束的 witness，并得到接受结果。
2. **所有权授权**：只有能够针对当前消息提供有效所有者签名的证明者，才能使转账获得授权。
3. **消息绑定**：签名必须绑定当前的 `noteSecret` 和完整的 `context`。如果其中任一相关值发生变化，原有签名不应继续授权新的消息。
4. **承诺绑定**：用于签名验证的所有者公钥、`noteSecret` 以及计算出的所有者承诺必须属于同一授权关系，并与 `expectedCommitment` 一致。
5. **组合判定**：有效签名与承诺匹配缺一不可；任一条件不成立时，电路都不应输出 `accepted = 1`。
6. **证明语义一致**：任何满足电路约束并得到接受结果的 witness，都必须表示一笔符合上述所有权授权要求的转账。

## 必要术语

- **Zkopru**：面向以太坊的隐私型 Layer 2 协议，使用零知识证明处理和验证隐私交易。
- **Layer 2 / Rollup**：在主链之外处理或聚合交易，并将必要的状态或验证信息提交到主链的扩展机制。
- **UTXO / note**：尚未被花费的交易输出。在隐私系统中，note 通常包含所有者和资产等秘密信息，并以承诺形式记录。
- **承诺（commitment）**：对一组数据计算得到的隐藏表示。它隐藏原始数据，同时将证明绑定到确定的数据内容。
- **所有权证明（ownership proof）**：证明某次资产操作得到了相应所有者授权的电路检查。
- **EdDSA 签名**：一种数字签名。验证者使用公钥检查签名是否由对应私钥持有者针对特定消息生成。
- **Poseidon**：为零知识证明场景设计的哈希函数。案例中的模板名称保留了项目的相关命名，但研究用代码以简化算术表达模拟摘要和验证数据流。
- **Witness**：证明者为电路中的输入和中间信号提供的一组具体取值。
- **约束（constraint）**：电路要求 witness 满足的代数关系；只有满足全部约束的 witness 才能生成有效证明。
