# Case 06：Panther 交易区域许可检查

## 案例背景

Panther Protocol 的 Shielded Pool 可以划分为具有不同准入和合规规则的 Zone。Zone Manager 可配置哪些区域之间允许进行私密资产活动。交易电路需要证明目标 `zoneId` 与策略列表中指定位置的许可区域一致。

## 代码在项目中的位置

本案例是从 Panther 的 `ZoneIdInclusionProver` 提炼出的研究用对齐版本。`ZoneCircuit` 调用私密交易组件；交易组件检查区域许可列表的摘要，并根据 `zoneOffset` 选择六个允许区域中的一项与 `zoneId` 比较。

案例使用显式六元素数组代替生产代码中的打包区域字段，但保留了列表位置选择、条件相等检查和交易标签数据流。

## 预期功能

1. 将 `zoneOffset` 解释为六项许可列表中的有效位置。
2. 读取 `allowedZoneIds[zoneOffset]` 并要求它等于 `zoneId`。
3. 汇总完整许可列表并与 `expectedListDigest` 对照。
4. 将通过检查的区域、位置和交易 nonce 绑定到最终标签。

## 输入信号及其语义

| 输入信号 | 形状 | 语义 |
|---|---:|---|
| `zoneId` | 标量 | 本次交易声明使用的区域标识。 |
| `zoneOffset` | 标量 | `zoneId` 在许可区域列表中的位置，应指向六个有效槽位之一。 |
| `allowedZoneIds` | `[6]` | 当前策略允许的六个区域标识。 |
| `expectedListDigest` | 标量 | 完整许可区域列表应当匹配的预期摘要。 |
| `transactionNonce` | 标量 | 区分本次私密交易的上下文值。 |

## 输出信号及其语义

| 输出信号 | 形状 | 语义 |
|---|---:|---|
| `tag` | 标量 | 绑定已验证区域、列表位置和交易 nonce 的结果标签。 |

## 必须满足的关键安全与功能性质

1. **位置有效性**：`zoneOffset` 必须指向 `allowedZoneIds` 的一个真实槽位。
2. **位置相等性**：`zoneId` 必须等于所选槽位中的区域标识。
3. **全槽位支持**：六个合法位置应具有相同的检查语义，包括首尾位置。
4. **禁止空检查**：任何可接受 witness 中必须恰好激活一个位置比较。
5. **列表绑定**：许可列表必须与 `expectedListDigest` 一致。
6. **交易绑定**：最终标签必须绑定验证后的区域、位置和 nonce。

## 必要术语

- **Zone**：Panther Shielded Pool 中具有特定准入、资产和合规规则的逻辑区域。
- **Zone ID**：标识某个 Zone 的数值。
- **Offset**：元素在有序列表中的位置编号。
- **许可列表**：策略明确允许交易交互的一组区域。
- **条件相等检查**：只在给定选择条件成立时要求两个值相等的约束组件。
- **Nonce**：区分不同交易实例的上下文值。
